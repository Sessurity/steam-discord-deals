# 🎮 Steam Discounts → Discord (UA)

Автоматично публікує добірку **до 20 ігор зі знижками від 70%** у Discord щодня о **08:00 за Києвом**. **SPORE** завжди першою, незалежно від розміру знижки. Не потребує ввімкненого комп'ютера, платних API або доступу до Steam-акаунта.

## Швидке налаштування

1. **Discord:** на своєму сервері відкрий налаштування каналу `#steam-знижки` → **Інтеграції → Вебхуки → Створити вебхук**. Назви його `Steam Deals`. Скопіюй URL. **Не надсилай URL у чат і не додавай у код!**
2. **GitHub:** створи **окремий новий репозиторій** `steam-discord-deals` під власним акаунтом (рекомендовано *Private*). Не використовуй існуючі репозиторії з ігровими проєктами.
3. Додай у нього **всі файли цього архіву**, зберігаючи каталоги `.github/workflows/` і `data/`. Найзручніше залити папку через `git` або попросити ChatGPT додати ці файли до щойно створеного репозиторію через підключення GitHub.
4. У репозиторії відкрий **Settings → Secrets and variables → Actions → New repository secret**. Ім'я: `DISCORD_WEBHOOK_URL`. Значення: скопійований Discord URL. Натисни **Add secret**.
5. Відкрий **Actions → Steam discounts → Discord → Run workflow**. Перевір повідомлення в Discord та журнал запуску.
6. Далі GitHub Actions сам запускатиме перевірку щодня о 08:00 у часовому поясі `Europe/Kyiv`. Іноді запуск може затриматися з боку GitHub.

**Важливо:** якщо з'явиться запит дозволити Actions, увімкни їх у **Settings → Actions → General**. Для збереження історії між днями процесу також потрібне `Read and write permissions` для `GITHUB_TOKEN`, якщо налаштування репозиторію обмежують запис; workflow вже запитує `contents: write`.

## Звідки беруться знижки

- Steam Store `IStoreQueryService/Query` — відбирає ігри зі знижками, `country_code=UA`, без DLC, пакетів і наборів; ціни в регіональній валюті.
- Steam Store `api/appdetails` — окремо перевіряє SPORE (`app/17390`, `cc=ua`) і підтверджує валюту `UAH`.
- Список впорядковується за популярністю, позитивними відгуками та знижкою; 5 місць резервується для нових акцій, якщо їх виявлено.
- Історія останньої перевірки зберігається в `data/state.json`, щоб позначати нові або покращені знижки, і уникати повторного надсилання в той самий день.

Це **неофіційні відкриті магазинні інтерфейси Steam**. Steam може змінювати їхній формат або обмежити запити. У такому разі workflow завершується з помилкою, а не публікує вигадані ціни. Вказаний розклад — цільовий, точність до хвилини GitHub Actions не гарантує.

## Налаштування

На початку `steam_deals.py` можна змінити `MIN_DISCOUNT = 70`, `MAX_DEALS = 20`, `SPORE_APP_ID = 17390`.

## Тестування локально

```bash
python -m unittest discover -s tests -v
```

Для тестового надсилання з ПК секрет може задаватися змінною середовища `DISCORD_WEBHOOK_URL`, але **не записуй URL у файли репозиторію**.

## Безпека

Бот **не входить у Steam**, **не має доступу до твоїх ігор чи платіжних даних** і **не може купувати ігри**. Він має лише односторонній дозвіл на публікацію через окремий Discord Webhook. Якщо посилання потрапить до сторонніх — видали Webhook у Discord і створи новий.


## Автоматичне прибирання завершених акцій

Після оновлення бот публікує **один актуальний добовий звіт** о 08:00 і зберігає ID Discord-повідомлення. Щогодини, о **:15**, запускається контрольний перегляд Steam: якщо опублікована гра вже не має знижки від 70%, бот **редагує це саме повідомлення і прибирає гру**, не підміняючи її іншою до наступного ранку. SPORE залишається в окремому блоці та теж оновлюється. Якщо ціни не змінювалися, повідомлення не редагується.

Новий щоденний звіт надсилається о 08:00 наступного дня, а попереднє відстежуване повідомлення видаляється. **Старі повідомлення, створені до цього оновлення, автоматично змінити неможливо**: раніше ID не зберігався. Після встановлення змін запусти вручну **Actions → Steam discounts → Discord → Run workflow** (увімкнено `force_send`), щоб створити перший редагований звіт.

Якщо Steam тимчасово недоступний, очищення завершується з помилкою і попередній список залишається без змін до наступної успішної перевірки. Частота перевірки — щогодини; видалення не завжди миттєве.
