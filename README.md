# 🎮 Steam Discounts → Discord (UA)

Автоматично публікує добірку **до 30 ігор зі знижками від 70%** у Discord щодня о **08:00 за Києвом**. **SPORE** завжди першою, незалежно від розміру знижки. Не потребує ввімкненого комп'ютера, платних API або доступу до Steam-акаунта.

## Швидке налаштування

1. **Discord:** на своєму сервері відкрий налаштування каналу `#steam-знижки` → **Інтеграції → Вебхуки → Створити вебхук**. Назви його `Steam Deals`. Скопіюй URL. **Не надсилай URL у чат і не додавай у код!**
2. **GitHub:** створи **окремий новий репозиторій** `steam-discord-deals` під власним акаунтом (рекомендовано *Private*). Не використовуй існуючі репозиторії з ігровими проєктами.
3. Додай у нього **всі файли цього архіву**, зберігаючи каталоги `.github/workflows/` і `data/`. Найзручніше залити папку через `git` або попросити ChatGPT додати ці файли до щойно створеного репозиторію через підключення GitHub.
4. У репозиторії відкрий **Settings → Secrets and variables → Actions → New repository secret**. Ім'я: `DISCORD_WEBHOOK_URL`. Значення: скопійований Discord URL. Натисни **Add secret**.
5. Відкрий **Actions → Steam discounts → Discord → Run workflow**. Перевір повідомлення в Discord та журнал запуску.
6. Далі GitHub Actions сам запускатиме перевірку щодня о 08:00 у часовому поясі `Europe/Kyiv`. Іноді запуск може затриматися з боку GitHub.

**Важливо:** якщо з'явиться запит дозволити Actions, увімкни їх у **Settings → Actions → General**. Для збереження історії між днями процесу також потрібне `Read and write permissions` для `GITHUB_TOKEN`, якщо налаштування репозиторію обмежують запис; workflow вже запитує `contents: write`.

## Звідки беруться знижки

- Steam Store `IStoreQueryService/Query` — відбирає ігри зі знижками, `country_code=UA`, без DLC, пакетів і наборів; ціни в регіональній валюті.
- Steam Store `api/appdetails` — окремо перевіряє SPORE (`app/17390`, `cc=ua`) і підтверджує валюту `UAH`.
- **Спочатку відбираємо популярні ігри**: віддаємо перевагу пропозиціям із щонайменше 5 000 відгуків Steam і визначаємо найцікавіші за кількістю/оцінкою відгуків та знижкою. Коли популярних ігор недостатньо, решту до 30 добираємо з менш відомих. **Уже обрану добірку** впорядковуємо за відсотком знижки від найбільшого до найменшого. Це індикатор популярності, а не гарантований фільтр AAA/інді.
- Історія останньої перевірки зберігається в `data/state.json`, щоб позначати нові або покращені знижки, і уникати повторного надсилання в той самий день.

Це **неофіційні відкриті магазинні інтерфейси Steam**. Steam може змінювати їхній формат або обмежити запити. У такому разі workflow завершується з помилкою, а не публікує вигадані ціни. Вказаний розклад — цільовий, точність до хвилини GitHub Actions не гарантує.

## Автоматичне прибирання завершених акцій

Після оновлення бот публікує **один актуальний добовий звіт** о 08:00 і зберігає ID Discord-повідомлення. Щогодини, о **:15**, запускається контрольний перегляд Steam: якщо опублікована гра вже не має знижки від 70%, бот **редагує це саме повідомлення і прибирає гру**, не підміняючи її іншою до наступного ранку. SPORE залишається в окремому блоці та теж оновлюється. Якщо ціни не змінювалися, повідомлення не редагується.

Новий щоденний звіт надсилається о 08:00 наступного дня, а попереднє відстежуване повідомлення видаляється. **Старі повідомлення, створені до цього оновлення, автоматично змінити неможливо**: раніше ID не зберігався. Після встановлення змін запусти вручну **Actions → Steam discounts → Discord → Run workflow** (увімкнено `force_send`), щоб створити перший редагований звіт.

Якщо Steam тимчасово недоступний, очищення завершується з помилкою і попередній список залишається без змін до наступної успішної перевірки. Частота перевірки — щогодини; видалення не завжди миттєве.


## Дизайн ZHAXO × Steam Store (v2)

- **Бірюзовий заголовок ZHAXO**: дата, український регіон, кількість активних пропозицій, графік перевірок.
- **Окрема золотиста SPORE-картка** з обкладинкою та актуальною ціною, навіть коли немає знижки.
- **Кожній грі — окрема бірюзова Discord Embed-картка** з мініатюрою обкладинки праворуч, відсотком знижки, попередньою/новою ціною та прямим посиланням.
- Discord дозволяє не більше 10 Embed-карток в одному повідомленні, тому добірка з 30 ігор автоматично розділяється на **чотири повідомлення** (8 + 10 + 10 + 2 ігри). Вони надходять послідовно.
- Кожна година о :15 — редагуються вже опубліковані картки. Прострочена гра зникає з її початкової групи; якщо ціле додаткове повідомлення спорожніло, воно видаляється.
- Новий щоденний звіт замінює всі попередні повідомлення, ID яких було збережено. Старі звіти формату v1 теж видаляються під час наступного успішного денного запуску.
- Якщо потрібно побачити новий дизайн одразу, запусти **Run workflow** із прапорцем **force_send**. Без ручного запуску новий дизайн уперше з'явиться під час наступного успішного денного звіту.

Дані Steam отримуємо без логіна; обкладинки — з публічного Steam CDN. Discord використовує власний стиль інтерфейсу: змінюються лише тексти, кольори бічних смуг, мініатюри та блоки Embed.


## Перевірка видалення вручну

У **Actions → Steam discounts → Discord → Run workflow** вибери **run_mode: cleanup**. Це запускає очищення **без нового повідомлення**: змінюються лише картки, знижка на які вже завершилася або опустилася нижче 70%. Якщо жодна знижка ще не завершилася, Discord не зміниться — це очікувана поведінка. Звичайний режим **daily** надсилає свіжий звіт і замінює попередній, а прапорець **force_send** застосовується лише до **daily**.

 
## Команди Steam безпосередньо в Discord

Webhook може тільки відправляти повідомлення. Для читання запитів потрібен Discord Bot (окремий від Webhook).

### Налаштування Discord Bot

1. Відкрий https://discord.com/developers/applications → New Application → Bot. Назви бота ZHAXO Commands.
2. У Bot → Reset Token скопіюй Bot Token. У Privileged Gateway Intents увімкни Message Content Intent (без нього Discord API не поверне текст повідомлень).
3. Через Installation / OAuth2 запроси бота на свій сервер. Дозволи: View Channel, Read Message History, Send Messages, Embed Links. Administrator не потрібен.
4. У Discord увімкни Developer Mode та скопіюй числовий ID каналу #deals (Copy Channel ID).
5. У GitHub відкрий Settings → Secrets and variables → Actions → Secrets, створи секрет DISCORD_BOT_TOKEN зі значенням токена і секрет DISCORD_CHANNEL_ID з ID каналу.
6. Необов'язково: у Actions → Variables додай DISCORD_ALLOWED_USER_IDS (числові Discord User ID через кому), якщо команди має виконувати тільки обмежене коло користувачів. Інакше ними користуватимуться всі, хто може писати в канал.
7. Після додавання обох секретів автоматичні перевірки запускатимуться без окремої змінної ввімкнення. Якщо секретів немає, перевірка безпечно завершується без дій.
8. Для перевірки: Actions → Discord Steam Commands → Run workflow. Потім у Discord напиши !help та запусти перевірку знову або дочекайся чергової автоматичної.

### Команди

- !help — список можливостей
- !deals — до 30 актуальних знижок Steam від 70% (до трьох повідомлень із великими обкладинками)
- !deals 90 — до 30 ігор зі знижкою від 90% (до трьох повідомлень із великими обкладинками) (поріг 70–100%)
- !spore — ціна SPORE зараз
- !find Dying Light — пошук серед активних знижок від 70%

Перевірка каналу проводиться за графіком приблизно кожні 5 хвилин (через GitHub Actions; запуск може затримуватися). Для першого запуску враховуються лише команди за останні 10 хвилин. Запити не змінюють щоденний звіт або очищення завершених акцій. Команди не є довільним AI-чатом; підтримуються тільки зазначені дії.

Стан запитів — data/command_state.json (лише ID останнього повідомлення, без токенів). Не додавай Bot Token у код, issue або повідомлення. 


## Відновлення автоматичних запусків (листопад 2026)

GitHub не створював подій schedule для двох workflow, хоча ручні запускалися. Оновлено cron-вирази, щоб повторно зареєструвати розклади; додано журнал діагностики події GitHub, cron, UTC і київського часу. Щоденний звіт залишається о 08:00 за Києвом. Очищення тепер заплановане на **:17 щогодини**; команди — **кожні 5 хвилин, починаючи з :04**. Для Discord-команд більше не потрібна змінна DISCORD_COMMANDS_ENABLED — достатньо двох GitHub Secrets для Discord Bot.

Зміна cron і успішні модульні тести **не підтверджують, що GitHub надіслав schedule-подію**. Після оновлення перевір на сторінці Actions, чи з'явилися запуски з подією schedule. Якщо їх досі немає протягом кількох очікуваних інтервалів, відкрий відповідний workflow у GitHub Actions і перевір, чи він Enabled; за потреби увімкни через меню «…» → Enable workflow. GitHub не гарантує точної хвилини запуску та може пропускати черги під навантаженням. Для надійного відгуку на команди без очікування GitHub знадобиться постійно працюючий бот або інша зовнішня служба.


## Оформлення відповідей Steam — картки A та сортування (листопад 2026)

- Для команд `!deals`, `!deals 90` та `!find назва`: **окремий Embed на кожну гру** з великою обкладинкою Steam (image, не маленький thumbnail), відсотком, старою та новою ціною, датою завершення (коли Steam її повідомляє) й посиланням.
- **30 ігор = до 3 Discord-повідомлень по 10 карток**. Це ліміти Discord, а не 30 окремих повідомлень.
- Ігри в командах і **нових щоденних звітах** впорядковуються за знижкою від найбільшої до найменшої; за однакової знижки — за рейтингом відгуків/популярністю. SPORE завжди окремим першим пріоритетом.
- Ігри, вже розміщені в добовому звіті, залишаються у своїх групах під час очищення; новий порядок застосовується під час наступної публікації звіту.
- Відображення команд залежить від фактичного запуску Discord Steam Commands (GitHub Actions schedule раніше не створював автоматичних запусків, це окрема проблема).


## Актуальність звіту та резервний запуск (03.11.2026)

- Шапка основного звіту показує **дату й час останньої успішної перевірки Steam** (за Києвом), а не лише час останньої зміни цін. Якщо ігри не змінилися, бот редагує тільки перше повідомлення, оновлюючи час.
- Якщо GitHub пропускає запуск о 08:00, **найближча подія schedule після 08:00** автоматично створить новий звіт, якщо сьогодні ще не публікували його. Додані резервні cron о 08:23, 08:43 і 09:13; щогодинний о :17 залишається. GitHub може затримувати або пропускати scheduled jobs, тож точного часу це не гарантує.
- Ручний запуск із режимом `cleanup` **не** запускає новий звіт; `SCHEDULED_RUN` встановлюється лише для scheduled jobs.
- Поле `last_checked_at` зберігає точний час успішної перевірки в `data/state.json`.


## Єдиний ZHAXO Discord Bot — з 3 листопада 2026

Відтепер **усі нові звіти Steam і відповіді на команди** надсилає вже підключений Discord-бот ZHAXO (Bot API). Старий Webhook більше **не публікує нові повідомлення**. Окремі GitHub Actions workflow зберігаються для двох графіків: звіти/очищення й команди, але у Discord автор один.

- Головний workflow використовує **`DISCORD_BOT_TOKEN`** та **`DISCORD_CHANNEL_ID`** (ті самі GitHub Secrets, що в Discord Steam Commands). Бот має дозволи Send Messages і Embed Links у каналі.
- Новий звіт ZHAXO містить 30 ігор, SPORE, обкладинки, знижки від 70%, сортування за знижкою та погодинне очищення. Bot API редагує й видаляє тільки власні повідомлення.
- **Міграція:** наступний scheduled cleanup після 08:00, якщо ще є старий Webhook-звіт, створить новий звіт ZHAXO. Також можна вручну виконати `Run workflow → daily → force_send`. Після збереження нових ID бот спробує видалити старі Webhook-повідомлення за допомогою старого секрету `DISCORD_WEBHOOK_URL`. Якщо видалення не вдалося, ID залишаються в `pending_message_batches` і видалення повториться на наступних запусках.
- **Не видаляйте** старий Webhook або його секрет до того, як старі Webhook-повідомлення зникнуть і `pending_message_batches` спорожніє. Після цього Webhook можна вимкнути в Discord та прибрати `DISCORD_WEBHOOK_URL` із GitHub Secrets.
- Ручний режим `cleanup` як і раніше не створює новий звіт; він лише редагує звіт наявного власника.

**Безпека:** токени Discord залишаються лише у GitHub Secrets, не зберігаються у state.json чи репозиторії.


## Пріоритет популярних ігор (03.11.2026)

Раніше відбір `sorted(deals, key=deal_sort_key)[:30]` надавав перевагу майже невідомим іграм із −95%/−99%. Відтепер: **відбір за популярністю (кількість і позитивність відгуків)**, із перевагою ігор із **5 000+ відгуків**, і тільки потім **сортування вибраних ігор за розміром знижки**. Таку саму логіку застосовано до `!deals` та `!deals 90`; для `!deals 90` відбір проводиться лише серед ігор зі знижкою від 90%. Збережено 30 позицій, українські ціни, SPORE, дизайн ZHAXO та видалення завершених акцій. Критерій базується на доступних даних Steam і не є класифікацією AAA.
